# 네이버 부동산 API 통신 구조 및 파라미터 설계 분석

## 1. 개요
네이버 부동산 모바일 웹 구조(`m.land.naver.com`)의 비공식 API를 리버스 엔지니어링하여 동적 렌더링(Selenium 등) 없이 JSON 데이터만 빠르고 가볍게 수집하는 구조입니다.

## 2. 주요 통신 엔드포인트(Endpoint)
1. **단지 목록 및 클러스터링 조회**
   - `GET https://m.land.naver.com/cluster/clusterList`
   - 목적: 지도 축소 상태에서 특정 지역 내의 단지 고유 번호(`hscpNo`) 및 구역 데이터를 가져옵니다.
2. **단지별 상세 매물 리스트 조회**
   - `GET https://m.land.naver.com/cluster/ajax/articleList`
   - 목적: 특정 단지(`hscpNo`) 내의 실제 매물들의 가격, 층수, 면적 등 구체적인 매물 리스트를 페이징 단위로 가져옵니다.

## 3. 핵심 검색 파라미터 (Query Parameters)
크롤링 요청 시 타겟팅할 필터 조합입니다.
- `rletTpCd` (매물 종류): 
  - `APT`: 아파트, `OPST`: 오피스텔, `VL`: 빌라/다세대
- `tradTpCd` (거래 방식): 
  - `A1`: 매매, `B1`: 전세, `B2`: 월세
- `hscpNo` (단지 번호): 특정 아파트 단지를 식별
- `z` (지도 확대 레벨): 보통 12 이상의 높은 줌 레벨을 사용해야 모든 정보가 누락되지 않음

## 4. 응답(Response) JSON 구조 및 수집 대상 키값
응답값인 `articleList` (배열) 내부에 있는 각 객체들이 부동산 실제 데이터입니다. 데이터프레임으로 만들 컬럼 헤더이기도 합니다.
- **수집 키값 명세**:
  - `atclNo`: 매물 고유 번호 (데이터 중복 제거 식별자, 테이블의 `Primary Key` 역할)
  - `atclNm`: 아파트/단지 이름
  - `prc`: 매물 호가 (예: "30,000" -> 3억 원 단위)
  - `rentPrc`: 월세 가격 (월세 거래일 경우)
  - `spc1` / `spc2`: 면적 정보 (공급 면적 / 전용 면적 ㎡)
  - `flrInfo`: 상세 층수 (예: "12/25" -> 25층 중 12층)
  - `direction`: 거실 기준 향 (예: 남동향)

## 5. 단계적 파이썬 구현 계획 (`naver_crawler.py` 방향성)
위 설계를 바탕으로 다음과 같은 순서의 파이썬 코드를 작성하고자 합니다.
1. `requests.Session()` 인스턴스를 유지하며, 봇 차단 방지용 모바일 `User-Agent` 설정 적용
2. 테스트용으로 주요 법정동의 단지 번호(`hscpNo`) 샘플 리스트를 순회 (`for-loop` 스케줄링)
3. 수집된 JSON 객체 리스트를 `pandas.DataFrame` 객체로 파싱
4. 판다스 내부의 `drop_duplicates(subset=['atclNo'])` 로직으로 중복 제거
5. `data/csv_exports/{오늘_날짜}_seoul_real_estate.csv` 로 결과 내보내기

***

> **피드백 요청**: Rule 2 (No-Code First)에 따라 네이버 크롤링에 대한 데이터 구조 설계를 먼저 작성했습니다. 이대로 스크립트화(작성)를 지시해주시면 다음 태스크(2.3)인 파이썬 로직 코딩으로 넘어가겠습니다!
